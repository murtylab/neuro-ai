Encoding Models

Can a neuron be built out of a model's units? An encoding model is the attempt: a weighted sum of model features that is meant to behave like a real neuron or voxel, and is tested on images it has never seen.

N. Apurva Ratan Murty, PhD
Assistant Professor, School of Psychological and Brain Sciences · Georgia Tech
murtylab.com ↗

Content check by Mainak Deb, Alish Dipani, and Nikolas McNeal

Another popular way to compare brains and models is with encoding models. Here the question is more direct: can we use the activity inside a model to predict what happens in the brain?

Suppose we show a stimulus to a neural network and record the responses of all the units in one layer. We then ask whether some combination of those responses can predict a particular measurement from the brain. That measurement could be the response of a single neuron, an fMRI voxel, an ECoG electrode, an MEG sensor, or really any other measurement of brain activity. We learn that relationship separately for each measurement.

Once the weights are fit, the real test is whether they generalize to new stimuli. We take a stimulus that played no role in fitting the encoding model, pass it through the network, and use the resulting activations to predict the brain response. We then compare that prediction with what the neuron, voxel, or other brain measurement actually did.

If the predictions are accurate for stimuli that were never used to fit the encoding model, we have learned something important: the model has learned features that provide a useful basis for constructing the brain's response. In other words, the model represents the stimulus in a way that can be transformed into the responses we actually measure in the brain.

01Intuition

The intuition

Can you build a neuron out of the model's units?

Take a real neuron and show it a set of images. Some images will make it respond strongly, others weakly. Now show those same images to a neural network and record the responses of all the units in one layer.

The question is: can we combine those model units to reproduce the response of the real neuron? Perhaps we need a lot of one unit, a little of another, and none of a third. We assign a weight to each unit and add their responses together. The result is our prediction of what the real neuron will do.

That is an encoding model. You can think of it as building a synthetic neuron from the model's units. Fitting the encoding model simply means finding the set of weights that makes this synthetic neuron behave as much like the real neuron as possible.

But there is an important catch. Doing well on the images used to find the weights tells us very little. With enough model units, we may be able to fit those responses simply because we have enough flexibility.

The real test is to show the model new images that played no role in choosing the weights. Does our synthetic neuron still predict when the real neuron will respond strongly and when it will respond weakly?

If it does, then the model has learned something useful about the neuron's response. Its units provide a basis from which we can predict the neuron's responses to new images. And we can repeat exactly the same procedure for a voxel, an electrode, or almost any other measurement of brain activity.

The claim being tested

A high held-out correlation says the neuron is, to a good approximation, a linear readout of this layer. The weights are the recipe. A low held-out correlation says the layer does not contain the ingredients, however well the training images were matched.

02Many features

Many features, one voxel

A voxel pools thousands of neurons. Expect it to care about more than one thing.

A voxel pools responses from many neurons, so we should not expect its response to depend on just one thing. Instead, we can give the encoding model many model units and let it learn how much each one matters.

The prediction is a weighted sum of the model units. Each model unit gets a weight: a large weight means that unit contributes strongly to the predicted response, while a weight near zero means it contributes very little. Together, the weights tell us which model units are useful for predicting that voxel, and how much each contributes.

Neuron/voxel-wise encoding model
$$\hat{y}_s \;=\; \sum_{k=1}^{p} w_k\,x_{sk} \;+\; b \;=\; \mathbf{w}^{\!\top}\mathbf{x}_s + b$$
$\mathbf{x}_s$ holds the $p$ features of image $s$; $\mathbf{w}$ holds one weight per feature. Every voxel gets its own $\mathbf{w}$, fitted separately, which is why the method is called voxelwise encoding.
03Implementation

How it actually gets done

Stack the images into a matrix, solve for the weights, multiply to predict.

Everything above considered one neuron or voxel at a time, using only a handful of model units. In practice, we might run hundreds or thousands of images through a network, take the responses of thousands of model units, and fit encoding models for many neurons or voxels at once. The bookkeeping is just matrix multiplication, so it helps to see how the pieces fit together.

The design matrix

Put the model's features in a matrix $\mathbf{X}$ with one row per image and one column per unit. Put the measured responses in $\mathbf{Y}$ with one row per image and one column per neuron or voxel. The weights $\mathbf{W}$ then have one column per neuron or voxel, and the whole model is one product.

The model, in matrix form
$$\underbrace{\hat{\mathbf{Y}}}_{S \times V} \;=\; \underbrace{\mathbf{X}}_{S \times p}\,\underbrace{\mathbf{W}}_{p \times V}$$
$S$ images, $p$ features, $V$ voxels. Column $v$ of $\mathbf{W}$ is the encoding model for voxel $v$. Nothing couples the voxels: fitting all of them at once is the same as fitting each separately, just faster.

W is the only thing that is learned: on the training images it is chosen to make Ŷ = XW as close to Y as possible. It is then frozen and applied to images it never saw. The correlation between Ŷ and Y on those held-out images is the model's score.

How do we get the weights?

We need to find the weights that make our predictions match the brain responses as closely as possible. Fortunately, this is a problem linear algebra knows how to solve.

There is one complication. We often have thousands of model units but only hundreds of images. That means there are many possible ways to combine the model units to fit the responses we measured. Some combinations may fit the training images extremely well, but only because they have picked up on noise. Give them a new image, and the prediction falls apart.

So we add a constraint: prefer solutions that do not rely on unnecessarily large weights. This is called regularization. Ridge regression does exactly this. It still tries to predict the brain responses well, but it also keeps the weights under control.

The parameter $\lambda$ controls that tradeoff. A small $\lambda$ gives the encoding model more freedom; a large $\lambda$ constrains the weights more strongly. We choose $\lambda$ using held-out data, asking which value gives us the best predictions for data that were not used to fit the weights.

Ridge solution
$$\hat{\mathbf{W}} \;=\; \big(\mathbf{X}^{\!\top}\mathbf{X} + \lambda \mathbf{I}\big)^{-1}\mathbf{X}^{\!\top}\mathbf{Y}$$
$\mathbf{X}^{\!\top}\mathbf{X}$ is $p \times p$ and does not depend on the voxels, so it is inverted once and reused for all of them. With $\lambda = 0$ and $p > S$ the matrix is singular and the fit is undefined, which is the algebraic version of the overfitting described above.

The whole thing in Python

With features in X (images × units) and responses in Y (images × voxels):

# X: (n_images, n_units) from a network layer
# Y: (n_images, n_voxels) measured responses
import numpy as np
from sklearn.linear_model import Ridge
from sklearn.model_selection import GroupKFold, cross_val_score
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline

# 1. split: hold out images the model never sees
train, test = np.arange(len(X)) % 5 != 0, np.arange(len(X)) % 5 == 0

# 2. choose lambda by cross-validation INSIDE the training set
lambdas = np.logspace(0, 6, 13)
scores = [cross_val_score(make_pipeline(StandardScaler(), Ridge(alpha=a)),
                          X[train], Y[train], cv=5).mean() for a in lambdas]
best = lambdas[int(np.argmax(scores))]

# 3. fit all voxels at once; Ridge handles a 2-D Y
model = make_pipeline(StandardScaler(), Ridge(alpha=best)).fit(X[train], Y[train])

# 4. predict the held-out images and score each voxel
Y_hat = model.predict(X[test])
r = np.array([np.corrcoef(Y_hat[:, v], Y[test][:, v])[0, 1]
              for v in range(Y.shape[1])])

# 5. noise ceiling: correlate two independent runs of the same voxels
ceiling = np.array([np.corrcoef(run1[test][:, v], run2[test][:, v])[0, 1]
                    for v in range(Y.shape[1])])
normalized = r / np.sqrt(np.maximum(ceiling, 1e-6))
Details that matter in practice

Group your splits. If the same image was shown in several runs, keep all its repetitions on the same side of the split, or the model sees the test images during fitting.

Fit the scaler on training data only. Computing the mean and standard deviation over all images leaks information about the held-out set.

Average repetitions before fitting to raise the signal, and keep the unaveraged runs for the noise ceiling.

04Noise

How high can the prediction go?

A voxel cannot predict itself perfectly. Neither can a model.

The same logic as in RSA applies, one voxel at a time. Measure a voxel twice and correlate the two runs. That correlation tells us how much of the voxel's response is reliable signal rather than noise. A model cannot be expected to predict the noise, so the reliability sets the bar.

A model that predicts a ventral voxel at 0.55 against a ceiling of 0.6 has captured nearly all the predictable structure. The same 0.55 against a ceiling of 0.95 has missed most of it. Report both numbers, or report the ratio.

05Procedure

The whole method in five steps

Features in, weights fitted, held-out images predicted, ceiling reported.

  1. Extract features. Run every image through the model and record a layer's activations. One row per image, one column per unit.
  2. Split the images. Set aside a group of images the model will never be fitted on. Harder still: hold out a whole category, so the test images are a kind the model has not seen at all.
  3. Fit the weights. Stack the features into $\mathbf{X}$ and the responses into $\mathbf{Y}$, then solve $\hat{\mathbf{W}} = (\mathbf{X}^{\!\top}\mathbf{X} + \lambda\mathbf{I})^{-1}\mathbf{X}^{\!\top}\mathbf{Y}$ on the training images, with $\lambda$ chosen by cross-validation inside that training set.
  4. Predict the held-out images and correlate the predictions with the measured responses. One score per voxel.
  5. Report against the noise ceiling, and repeat the whole procedure for every layer and every region. The pattern of scores is the result.
06Neuroscience

Early results with encoding models

Good at the task, and therefore a good basis for the brain?

A classic example comes from Yamins and colleagues in 2014. They recorded from neurons in macaque V4 and IT while the animals viewed thousands of images of objects. The objects varied widely in position, size, pose, and background, making recognition challenging.

The authors then searched for models that were good at an engineering task, object recognition. Importantly, the neural data played no role in choosing the model. Only after selecting the best-performing model did they ask whether its model units could be combined to predict the response of each neuron.

This connected two questions that had previously been largely separate. Which models perform well at object recognition? And do models that perform well also provide a good basis for predicting responses in the primate visual system?

Figure 4 — The two-step logic: optimize the model for a task, then test its per-site neural predictions
From the paper
Each layer applies the same set of operations: filter, threshold, pool, normalize. Step 1 searches over architectures and keeps the ones that categorize objects well, using no brain data at all. Step 2 takes the resulting fixed model and asks, one recording site at a time, whether a linear weighting of a layer's units predicts that site's response to held-out images. Figure from Yamins et al. (2014), PNAS 111:8619–8624, reproduced for teaching.

The answer was yes. The model's top layer could explain about half of the reliable variation in IT neurons, roughly twice as much as the control models. And something interesting happened across the hierarchy. An earlier layer was better at predicting V4, while the top layer was better at predicting IT. The stages of the model seemed to line up with the stages of the visual system, even though the model had never been trained to do that.

But the bigger result came from looking across all the models they tested. The better a model was at recognizing objects, the better it was at predicting IT neurons. Models that got better at the engineering task also became better models of the brain.

And this was not just because the model knew whether an image contained a face, a car, or a chair. Category labels alone could not predict the neurons nearly as well. Something about the representation the model had learned for solving object recognition also provided a useful basis for predicting how IT neurons respond.

01 · Encoding model

Features → response

A fitted function from a model's features to one voxel's response to each image.

02 · Voxelwise

One $\mathbf{w}$ per voxel

Weights are fitted separately for every voxel. The weights describe what that voxel listens to.

03 · Held-out test

Images never fitted

The only score that counts. Harder version: hold out an entire category.

04 · Ridge

$(\mathbf{X}^{\!\top}\mathbf{X}+\lambda\mathbf{I})^{-1}\mathbf{X}^{\!\top}\mathbf{Y}$

Penalizes large weights so correlated features cannot cancel noise, and makes the inverse exist when $p > S$.

05 · Noise ceiling

Voxel vs itself

Run-to-run reliability of each voxel. The bar a model's prediction is read against.

06 · Held-out score

Prediction on new images

The correlation between predicted and measured responses on images the weights never saw, read against the noise ceiling.

Encoding and RSA answer different questions about the same pair of systems. RSA asks whether the arrangements agree. Encoding asks whether one system's features can produce the other's responses. A linear map from thousands of units is itself flexible, so a model is judged on held-out images and against the noise ceiling, not by a single high score on the images it was fit on.
